## Goals

1. Add a public `/welcome` landing page while preserving `/` as the reservation app route required by the existing browser tests.
2. Keep the current cream / deep-green / warm-gold visual language, but make the product feel like a real restaurant discovery and reservation product rather than a form-first demo.
3. Populate normal startup with four demo restaurants: Ember & Oak, The Green Fork, Palm & Plate, and The Olive Room. Pair each with its matching local image.
4. Add a polished restaurant-card discovery section with image, cuisine/type, location/time-zone hint where useful, and a clear action into availability.
5. Add the confirmation illustration to the success state; use local icons for search, date, guests, location, clock, table, availability, retry, and no-double-booking messaging.
6. Add subtle CSS motion only where helpful; preserve reduced-motion behavior.
7. Serve all assets locally from the application. Never introduce third-party image URLs or a CDN dependency.
8. Keep all existing route/test IDs and reservation/idempotency/replan behavior intact.
9. Preserve the Stage 1–4 contracts and run the complete existing checks after integration.

## Important hackathon discipline

The visual files were generated by the team as project assets. They are not a substitute for Band-produced application code. The Band Implementer must perform the code integration and commit the resulting code in the Band workspace so the room log and git history show the collaboration.
